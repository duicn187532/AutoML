# 模型 × 資料相容性

> 測試方式：在瀏覽器（Chromium，無 GPU）中，對 14 個範例資料集逐一用「模型庫」的**預設參數**與 hold-out 驗證訓練全部 17 個模型，共 209 次（另含 Iris 16 次預先測試）；
> 單次上限 150 秒。表中為驗證集分數（分類：準確率；迴歸：RMSE）與耗時。
> 「n/a」= 該模型不支援此任務（例如 LDA / QDA / Naive Bayes 只能分類、Ridge 只能迴歸），選單中不會出現。

## 結論摘要

**沒有「資料型態無法使用某模型」的硬性限制。** 所有模型都接受數值、類別、日期、文字欄位，因為前處理會統一轉成數值矩陣：
數值標準化 + 缺值補值 / 指示欄、類別 one-hot（或 ordinal / target / hash）、日期拆成年 / 月 / 日 / 星期、文字轉 TF-IDF，ID 欄自動排除。
真正的限制有兩類：**資料量**（計算量或記憶體）與**模型假設不符**（能跑，但結果差）。

### 不是模型問題、但會讓結果失真的資料狀況
- **洩漏欄位**：Titanic 的 `alive`、單車的 `casual` + `registered`、銀行行銷的 `duration`。模型庫預設勾選所有欄位，因此 Titanic 全部模型 ≈ 100%、單車 Ridge 的 RMSE 只有 6.6。
  資料品質報告會標示，**訓練前請取消勾選**。
- **類別不平衡**（信用卡違約 22%、銀行行銷 12%）：準確率會偏高、看起來好。請看 AUC / F1，並在「門檻」頁調整決策門檻。目前沒有 class weight 選項。
- **偏態的迴歸目標**（房價）：RMSE 會被高價物件主導。可在「清理」用 `log1p` 轉換目標；但預測值也會是 log 尺度，需自行換回。

## 匯出支援

| 匯出 | 支援的模型 |
|---|---|
| Python 程式碼（重現前處理 + 模型） | 全部 |
| 單檔 HTML 預測器 / JavaScript runtime | 邏輯迴歸、Ridge、MLP（非 GELU）、sklearn 線性模型、決策樹、隨機森林、ExtraTrees、HistGBDT、XGBoost、LightGBM，以及由它們組成的 AutoML 集成 |
| ONNX | 同上的單一模型（AutoML 集成尚不支援） |
| 不支援 HTML / JS / ONNX | AdaBoost、SVM、kNN、Naive Bayes、LDA、QDA、高斯過程（只能用 Python 匯出） |

## 其他模組的限制
- **時間序列預測**：數值目標欄 + 日期或數值時間欄、至少 12 個不同時間點；單一序列（多個序列請先用「篩選列」分開）；時間間隔應大致規律。
- **架構編輯器**：表格資料可用 Dense / Block（MLP、Residual）/ Expert / Gate / Merge；Block 的 CNN / LSTM / Transformer 需要影像或序列輸入，選單中已標示並停用。
  異質 expert（XGBoost、RF 等）兩階段訓練只支援一個 gate 與一個 head。
- **影像**：只用於「影像資料夾」匯入的資料集（MobileNet 特徵 + head / fine-tune）。
